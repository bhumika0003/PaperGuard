PART 4: WHAT'S RUNNING?
================================================================================

When you start docker-compose, three things run:

1. securestack-app (ONE Container)
   Contains:
   - Frontend (React/Vite) on Port 3000 (inside), 8000 (your computer)
   - Backend (Express.js) on Port 7000 (inside), 8001 (your computer)

   Contains:
   - PostgreSQL database on Port 5432
   - Stores all your data

3. Docker Network (securestack-network)
   - Allows containers to talk to each other
   - You don't need to do anything with this

PART 5: HOW DATA FLOWS (Simple Explanation)
================================================================================

When a user registers:

STEP 1: User fills form in Frontend (http://localhost:8000)
   Email: testuser@example.com
   Password: password123
   Role: Teacher
   Department: Computer Science

STEP 2: Frontend sends data to Backend
   POST request to http://localhost:8001/api/auth/register
   Data is sent as JSON (special format)

STEP 3: Backend receives and processes
   - Checks if email is valid
   - Hashes the password (makes it unreadable: $2a$10$...)
   - Generates a unique User ID (like TCH-6698)
   - Creates a JWT token for login
   - Gets ready to save to database

STEP 4: Backend sends to Database
   SQL command: INSERT INTO Users table
   Adds new user record to PostgreSQL

STEP 5: Database confirms
   "User saved! User ID is TCH-6698"

STEP 6: Backend sends response to Frontend
   Returns: User ID, Email, Role, JWT Token

STEP 7: Frontend displays success message
   "Welcome testuser@example.com!"
   Stores JWT token for future requests

STEP 8: Data is now in Database
   Can be checked with SQL query:
   SELECT * FROM "Users" WHERE email = 'testuser@example.com'

PART 10: UNDERSTANDING THE SECURITY
================================================================================

Your application has these security features:

1. PASSWORD HASHING
   When user enters: "password123"
   What's saved in DB: "$2a$10$78fxVOXns6liXji/8EEQV..."
   ✅ Original password can NEVER be recovered
   ✅ Even if database is stolen, passwords are safe

2. JWT TOKENS
   After login, user gets: "eyJhbGciOiJIUzI1NiIsI..."
   ✅ Used for future requests
   ✅ Expires after some time
   ✅ Prevents unauthorized access

3. ROLE-BASED ACCESS
   Different users have different permissions:
   - Admin: Can do everything
   - Teacher: Can upload papers
   - HOD: Can view reports
   - Principal: Can access audit logs
   - Exam Controller: Can view data
   ✅ Prevents unauthorized actions

4. DATA INTEGRITY
   Question papers are hashed with SHA-256
   ✅ Can detect if file was changed
   ✅ Can verify file is original

PART 12: COMMON ISSUES & FIXES
================================================================================

ISSUE 1: Port 8000 or 8001 already in use
FIX: Kill the process using that port
   lsof -ti:8000 | xargs kill -9
   lsof -ti:8001 | xargs kill -9

Then restart:
   docker-compose up -d

ISSUE 2: Database not connecting
FIX: Wait longer for PostgreSQL to start
   Wait 30-40 seconds after docker-compose up

Or restart:
   docker-compose down --volumes
   docker-compose up -d

ISSUE 3: Frontend shows blank page
FIX: Clear browser cache
   Ctrl+Shift+Delete (or Cmd+Shift+Delete on Mac)

Or view logs:
   docker-compose logs securestack-app

ISSUE 4: Backend API not responding
FIX: Check if container is running
   docker ps

If not running, check logs:
   docker-compose logs securestack-app

Look for error messages

ISSUE 5: Can't access http://localhost:8000
FIX: Make sure containers are running
   docker ps

If not running:
   docker-compose up -d

Wait 30 seconds and try again

PART 14: HOW THE PORTS WORK
================================================================================

PORTS are like "doors" to access services:

Your Computer (Host)  →  Docker Container (Inside)

8000  →  3000   (Frontend)
   Your browser accesses localhost:8000
   This connects to port 3000 inside the container
   Where Vite is running

8001  →  7000   (Backend)
   Your API calls go to localhost:8001
   This connects to port 7000 inside the container
   Where Express.js is running

5432  →  5432   (Database)
   Database clients connect to localhost:5432
   This connects to port 5432 inside database container
   Where PostgreSQL is running

Example:
When you open http://localhost:8000:
1. Your browser sends request to localhost:8000
2. Docker redirects it to port 3000 inside container
3. Vite (frontend) receives and responds
4. You see the website

PART 15: DOCKER COMPOSE EXPLAINED
================================================================================

docker-compose.yml is a configuration file that tells Docker:

"I want to run 2 containers:"

Container 1: securestack-app
   - Build from: Dockerfile (current directory)
   - Name: securestack-app
   - Ports: 8000:3000 and 8001:7000
   - Environment: DB_HOST=postgres, DB_USER=postgres, etc.
   - Network: securestack-network
   - Depends on: postgres (wait for database before starting)

Container 2: securestack-db
   - Image: postgres:16 (pull from Docker Hub)
   - Name: securestack-db
   - Ports: 5432:5432
   - Environment: POSTGRES_PASSWORD=bhumi0309, POSTGRES_DB=securestack
   - Volumes: postgres_data:/var/lib/postgresql/data
   - Network: securestack-network

Plus Network:
   - Name: securestack-network (bridge type)
   - Allows containers to communicate by hostname

Plus Volume:
   - Name: postgres_data (persistent storage)
   - Keeps database files even when container restarts

PART 16: DATABASE SCHEMA (What's in Database)
================================================================================

The database has 6 tables:

1. Users
   Stores: user accounts
   Fields: id, userId, email, passwordHash, role, department, status
   Example: testuser123, Teacher, Computer Science

2. QuestionPapers
   Stores: exam papers
   Fields: paperId, title, subject, fileHash, status, uploadedBy
   Example: 3 papers (CS101, IT602, ET501)

3. AccessLogs
   Stores: who accessed what
   Fields: userId, paperId, action, timestamp
   Tracks: Download, View, Share, etc.

4. DownloadRequests
   Stores: download approvals
   Fields: userId, paperId, requestTime, status
   Status: Pending, Approved, Rejected

5. SecurityAlerts
   Stores: suspicious activities
   Fields: alertType, severity, description, userId, timestamp
   Example: Failed login attempts, unauthorized access

6. ChatMessages
   Stores: messages between users
   Fields: senderId, receiverId, message, timestamp, read
   For: Communication within system

PART 18: PM2 PROCESS MANAGER
================================================================================

PM2 is a tool that runs and manages Node.js applications.

Inside our container, PM2 manages:

1. backend-wait
   What: Runs Express.js backend
   Command: node ./backend/server.js
   Port: 7000
   Waits: 10 seconds before starting (for database to be ready)

2. frontend
   What: Runs Vite dev server for React
   Command: node_modules/.bin/vite
   Port: 3000
   Options: --host 0.0.0.0 (accessible from outside)

Benefits of PM2:
✅ Keeps services running automatically
✅ Restarts if services crash
✅ Shows process status
✅ Easy to restart individual services
✅ Manages multiple services in one container

View PM2 status:
   docker exec securestack-app pm2 list

PART 19: DATA PERSISTENCE (Why Data Doesn't Disappear)
================================================================================

When you restart Docker, your data is still there because of VOLUMES:

VOLUMES are like folders that survive container restart.

postgres_data volume:
   Location inside container: /var/lib/postgresql/data
   Location on your computer: Docker storage location
   Contains: All database files

When you:
   docker-compose down
   (Container stops, but volume stays)

Then:
   docker-compose up
   (Container starts, volume reconnects)

Result: All your data is still there! ✅

Exception: If you run:
   docker-compose down --volumes
   (This DELETES the volume - all data is gone)
